# CLIO Kronos — candlestick forecaster in DPOF's judgment layer

**Author:** Buddy (Atlas Genius, four-persona; Jev consulted per card v1.4) · **Date:** 2026-09-26 · **Class:** DESIGN FRAME → build spec.
**Origin (Dom, 2026-09-26):** "look at Kronos on the Hydrinia repo … an agent that can read charts like ChatGPT reads English … useful as part of the signal and judgment layer, from a quantitative technical perspective, for CLIO to make the decisions on when to trade."

## 0. One paragraph
A separate CLIO service runs Kronos (the open-source candlestick foundation model Hydrinia vendored, MIT) on SPY and QQQ 5-minute bars every 5 minutes during the regular session. It samples future price paths and writes, per symbol and horizon (15/30/60 min): the probability the price is higher, the expected and quantile returns, and the expected absolute move. It also scores every past forecast against what actually happened and writes a running track record. DPOF shows both to its decision model as one advisory technical input, at entry and at position reviews, and logs them next to the flow pillars. The composite, the Jev veto and every order path are unchanged. Promotion to a live composite pillar is the operator's call once the scored record exists.

## 3. The service (`agent/kronos/`, `python -m agent.kronos`)
- **Vendored model:** `agent/kronos/vendor/` = Hydrinia's `kronos_vendor/model/` (upstream `67b630e`, with Hydrinia's two documented import patches) + upstream `LICENSE` + a `VENDOR_PIN.md` (provenance, sha256 of the upstream tarball, the patches). Weights by pinned HF revision, loaded with `local_files_only=True`; a `--download` command fetches them once (deploy step).
- **Inputs:** regular-session 5-minute bars (09:30–16:00 ET, holidays/half-days from `agent.integrations.market_events` or the DPOF session helpers) for the configured symbols (default SPY, QQQ), lookback 400 bars (~5 sessions), OHLCV + amount (= volume × VWAP when the bar has one, else volume × close). Feed follows CLIO's broker settings (IEX default; record the feed used). Timestamps are the bar's ET wall-clock time.
- **Forecast:** `predict_batch` over all symbols with `sample_paths` (default 16) copies per symbol, T 1.0, top_p 0.9, a seed derived from the anchor bar time (reproducible); `pred_len` = 12 bars, truncated at the session close (horizons that would cross the close are omitted, never extrapolated overnight). Per horizon: p_up (ties half), mean/median/q10/q90 return %, expected |move| %.
- **Cadence:** a run 20 s after each 5-minute boundary from 09:35 to 15:55 ET on trading days; sleeps otherwise; one run at a time; each run bounded by a timeout. `torch.set_num_threads(CLIO_KRONOS_TORCH_THREADS, default 6, clamp 1–8; VPS sweep 2026-09-27: 4/6/8 threads → ~94/77/69 s, RSS ~1.5–1.6 GB)`; the unit adds `Nice=10` and a `CPUQuota=800%` ceiling (so threads are tunable by env alone). Measured 2026-09-27: a run takes ~91 s on the VPS (~34 s in a 4-core dev container) and peaks at ~1.5 GB RSS; the vendored model has no KV cache, so cost grows with batch × window × steps.
- **Scoring (status-driven, CLAUDE.md #36):** every forecast is appended to `data/intelligence/kronos_history.jsonl` (capped) with its anchor; each run resolves pending horizons whose target bar has closed, from the bars it just fetched (realized return vs the anchor close), and rewrites `kronos_scores.json` (per symbol × horizon, all-time and last 5 sessions: n, hit rate, confident-only hit rate (p_up ≥ .6 or ≤ .4), Brier of p_up, MAE of expected |move|). Unscored metrics are null, never 0.
- **Files:** `agent/kronos/state.py` is the contract (schema, paths, fresh reader, atomic writer) — already written; the service uses it unchanged.
- **Unit:** `systemd/clio-kronos.service` mirroring the flow collector's (User=agent, `ReadWritePaths=/home/agent/openclaw/data/intelligence`, read-only everything else, `Nice=10`, `CPUQuota=800%` ceiling, `MemoryHigh=2560M`/`MemoryMax=3072M`, restart on failure). Optional deps in `requirements-kronos.txt` (CPU torch, pandas, einops, safetensors, huggingface_hub); `agent.kronos` imports them lazily and exits cleanly with one log line when they are missing.
- **Knobs:** `CLIO_KRONOS_SYMBOLS` (SPY,QQQ), `CLIO_KRONOS_SAMPLE_PATHS` (16, clamp 2–64), `CLIO_KRONOS_LOOKBACK_BARS` (400, clamp 64–512), `CLIO_KRONOS_TORCH_THREADS` (6), `CLIO_KRONOS_RUN_TIMEOUT` (240 s), `CLIO_KRONOS_MODEL` / `_TOKENIZER` / revisions (pinned defaults).

## 4. DPOF consumer (`agent/dpof/`)
- `data.py` reads `state.read_forecast()` + `state.read_scores()` in an executor (like the vol surface) and attaches per-underlying `kronos` to the snapshot/context; stale or missing → the block says `unavailable` (never zeros).
- Decider context (entries AND position reviews): per underlying, each horizon's p_up / expected return / q10–q90 / expected |move|, the bar the forecast is as of, and the track record (n, hit rate, confident hit rate, Brier) — so the model can weight it by its record. One paragraph in the charter: an advisory technical input from a candlestick model, weigh it by its scored record, never the sole reason, it knows nothing about flow or news.
- Signal log: each cycle record gains `kronos` (p_up and expected return at 30 min, asof) and the Jev bucket words the log never kept (`gamma_regime`, `price_vs_vwap`, `momentum_15m`, `volatility`) so replays for the decision record become faithful (B2 finding).
- Telegram: `/dpof kronos` — latest forecast + track record per symbol; one line in the daily digest.
- Knob: `CLIO_DPOF_KRONOS_CONTEXT` (default 1 = shown; paper is the soak).

## 4b. Live pillar (operator directive, 2026-09-26)
- `kronos` joins `PILLAR_NAMES` as a DIRECTIONAL pillar: value = `2·p_up − 1` at `CLIO_DPOF_KRONOS_HORIZON` minutes (default 30; allowed 15/30/60; when that horizon is absent near the close, the longest available horizon below it), from a FRESH forecast only (`state.read_forecast`, max age `kronos_max_age_seconds`). Stale, missing, `status != ok` or no usable horizon → pillar unavailable (value None, never 0.0).
- Weight `w_kronos` (`CLIO_DPOF_W_KRONOS`, default 0.15) beside nofa .40 / premium .25 / darkpool .20. `compute_composite` is a weighted average over the available directional pillars, so the composite's scale and the thresholds keep their meaning; with Kronos unavailable the composite is byte-identical to today's.
- Kronos does NOT count toward `min_pillars` (flow evidence requirement unchanged: NOFA + ≥ 3 flow/GEX readings); it only adds direction to a composite that already qualifies.
- Knob `CLIO_DPOF_KRONOS_PILLAR` = `live` (default) | `off`. Rollback: `off` + restart (the context block has its own `CLIO_DPOF_KRONOS_CONTEXT`).
- Observability: the pillar value lands in the signal log with the other pillars; a Telegram alert (deduped per session) when the forecast goes stale for more than 15 minutes during the session.

## 5. Promotion
The pillar is live from day one (§4b). The scorer's record (n, hit rate, calibration by horizon) is the monitor: after ≥ 10 sessions it goes to Dom with a suggested weight change (up, down or off) — weight changes are env-only, no code change.
